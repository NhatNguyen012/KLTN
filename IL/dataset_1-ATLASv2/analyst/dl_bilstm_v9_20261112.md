# Single-BiLSTM detector on ATLASv2: root cause of low F1 and the v9 fix — 12 November 2026

Follows [dl_root_cause_20261111.md](dl_root_cause_20261111.md),
[dl_provenance_context_20261111.md](dl_provenance_context_20261111.md) and
[dl_process_graph_20261111.md](dl_process_graph_20261111.md). Those artifacts are
unchanged. All new code is in `code/DL/bilstm_v9/`; all outputs are in
`code/DL/output/bilstm_v9_20261112/`. Training used the local RTX 3050 (CUDA).

The task is the same as before: binary detection for each 180 s window (30 s stride)
of CBC-EDR events on the same scenario split (train S1–S3, M1, M2, M4 + benign
days 1–2; val M3, M5 + day 3; test S4, M6 + day 4). Windows, chunks, split and
day-boundary embargo are rebuilt by the same rules. Under the original labels
they reproduce the embargoed benchmark: 2,366 test windows, 38 positive.

## Root causes, in order of impact

### 1. About a third of test positives cannot be learned (label defect)
The legacy refiner marks a Firefox connection malicious when its endpoint is in
a REAPr `.seeds` file. Three seed endpoints also appear in the **benign-day**
telemetry, which the refiner treats as 100% benign by definition:

| Seed endpoint | Benign-day connections | What it is |
| --- | ---: | --- |
| 34.107.221.82:80 | 304 | Firefox captive-portal check (`detectportal.firefox.com`) |
| 142.250.191.225:443 | 58 | Google |
| 10.193.242.113:9997 | 22 | second experimenter's host (h2 benign) |

In the test set, **14 of 38** legacy-positive windows contain nothing but these
connections. The identical event is negative on day 4 and positive on attack day.
No feature set can separate them, so any honest model's recall tops out near 24/38
and F1 on the original labels near 0.75. That matches every run above, including
the earlier graph models. Rule for v9: a seed endpoint makes a connection
malicious only if it is never contacted in benign-day telemetry. The rule is set
from benign data, not from model output.

### 2. Attack start gates that are later than the attack (label defect)
`INITIAL_ATTACK_TIMESTAMPS` zeroes every event before the configured start. On
the h1 hosts, the first connection to the attacker host 10.193.66.115 lands within
about ±3 min of the configured gate for most scenarios. The exceptions:

* **S3** (train): gate 15:36, but the telemetry ends at 15:01, and the first attacker
  connection is at 14:33:24. As configured, S3 contributes no positives at all.
* **S4** (test): gate 00:52. Yet at 00:48:39 Firefox downloads `s4-at-night.zip`, at 00:48:51
  `msf.doc` is extracted, and at 00:49:16 and 00:50:45 `winword.exe` connects to
  `10.193.66.115:8080`. Both Word processes are REAPr attack processes. Windows
  w0028–w0036 therefore contain C2 traffic but are labeled benign. Every model flags
  them, and they show up as the recurring "false positives".
* M5 (val) is 12 min early, S1 (train) 7 min early.

v9 fixes only S3. v9b applies one rule to every scenario: gate = min(configured, first connection to the
attacker host). This adds 9 test positives (S4 Word/C2 and lsass→Word, M6 regsvr32→C2)
and 22 validation positives (mostly M5 Word/mshta C2 and cmd launches; a few are
capture tools started by a REAPr-flagged cmd). **Disclosure:** the S4 case surfaced
while examining test errors. The rule is uniform and depends only on the attacker
IP documented with the dataset, but v9b is not blind to the test set. That is why v9,
which only changes S3 and the seed rule, is reported alongside it, and still scores
F1 0.91–0.93.

### 3. Impoverished event representation
The old input had 4 categorical fields (a target basename substituted for the actor), a
host bit and Δt. It had no event type, actor/parent, relation, direction or command
line, and process starts, process handle opens and connections looked alike.
Even with the original labels, the v9 representation alone moves test F1 from
0.54 to 0.64 and the legacy-trained AP from 0.50 to 0.58. On clean labels, AP rises to 0.98–0.99.

v9 tokens per event: event kind (incl. cross-process sub-action and direction),
actor, actor directory class, parent, target, target directory class,
proto:port-class:has-domain, ip_scope, user class, actor/target signature state;
18 command-line switches (encoded, hidden window, bypass, URL, script extension,
download cradle, regsvr32 /i, cmd /c, long) for actor and child; Δt, relative
time, and file-modification flag. File modifications of executables, scripts, archives and documents are
input-only events, never label sources. TRAIN-only vocabulary, min count 2.
GUIDs, IPs, domains, scenario, host identity and reputation verdicts are excluded.

### 4. Training and selection noise
At lr 2e-3, validation F1 jumped between 0.55 and 0.96 across adjacent epochs, so
picking the best epoch produced seed outcomes from 0.61 to 1.00. Sigmoid outputs also
saturated in float32: the selected threshold was 0.9999992, and test scores tied at 1.0.
Fixes: lr 5e-4 with OneCycle over 20 epochs; thresholds chosen in logit space. Seed
std on v9 dropped from 0.136 to 0.027. Weight averaging (SWA) was tried and
rejected: it averages overfit late epochs, and validation F1 fell to 0.80–0.85.

## Model

`BiLSTMDetector` (`bilstm_v9/train.py`) is a single model with 812k parameters:
per-field embeddings + numeric features → Linear(128)+LayerNorm+GELU → 2-layer
BiLSTM(128 per direction) → two heads:
* a per-event head, trained with an auxiliary event-label BCE (weight 0.5, sqrt pos_weight).
  The window score from this head is its max event logit (multiple-instance pooling);
* a window head on attention ⊕ max pooling, trained with window BCE.
The head is chosen on validation by (AP + best F1)/2. In practice it was the event-max
head in 58 of 64 runs. Training uses token dropout of 0.1 to `<UNK>`, AdamW, grad clip 1.0,
and all train negatives (no undersampling).

## Shortcut check
`ip_scope=PRIV_10` is almost an IOC in this testbed. Benign days contain 29
connections to 10.x out of ~20k, while attack-day 10.x traffic is mostly the attacker.
Removing it barely changes ranking (v9b AP 0.998 → 0.993) and costs about 3 F1 points,
so the recommended model drops it. Removing signature state and command-line flags as
well also leaves AP ≥ 0.99. The model relies on process lineage and behaviour (Office
→ script host → PowerShell, `payload.exe`, abnormal handle access), not one token.

## Caveats you must state
* **Attack redundancy.** The REAPr README warns that all ten ATLASv2 attacks are
  near-identical chains, so training on some attacks is close to training on
  the others. A high F1 means "recognises variants of known chains", not detection
  of novel APTs.
* Only two test scenarios. Windows overlap 5/6, so 33 positive windows are not 33
  independent attacks. Seeds measure training variance, not campaign variance.
* v9/v9b are label **corrections with evidence**, not new gold truth.
  Always publish the original-label column next to them.
* Stage classification (the five-stage head) is out of scope here. This is binary detection only.

## Addendum (12 Nov 2026, later): attack-stage results and LightGBM with the new labels

### A. Stage results for the single BiLSTM

**Change.** A per-event stage head (4 classes) was added to the same BiLSTM and trained
with cross-entropy (weight 0.5, inverse-sqrt class weights) on **positive events
only**. Stage targets are REAPr's process-level `stage` column. Per the research
policy these are weak, process-name-based labels, not verified tactics. Binary
detection, checkpoint selection and threshold are unchanged (validation only).

**Two stage tasks.** Both are evaluated on **all** test windows, so a stage
predicted on a benign window counts as an error:
* **Presence** (multi-label): which stages occur anywhere in the window.
  Per stage, the score is s_k = max_t [log p_attack(t) + log q_k(t)]. A stage is
  predicted if the window alerts and s_k ≥ τ_k, with τ_k chosen on validation.
* **Last stage** (5-class incl. benign, the historical target): the stage of the
  last alerting event in an alerting window.

**Test support (windows).** Under v9b, presence is IC 15 / ED 24 / LM 6 / EX 18,
and last stage is IC 9 / ED 6 / **LM 0** / EX 18. Under the original labels, all
8 Lateral-Movement last-stage windows are the h2 Firefox captive-portal windows
(root cause 1), which no model can learn. Once those are corrected, no test window
ends in Lateral Movement. LM is therefore only measurable as presence. Macro
averages are given both over stages with test support and over the fixed 4 classes.

Results (5 seeds, mean ± std, `output/bilstm_v9_20261112/sweep6/`, `stage_summary.json`):

| Training/eval labels | Binary F1 | Presence macro F1 (4) | IC | ED | LM | EX | Last-stage macro F1 (supported) | Last-stage macro F1 (fixed 4) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| original | 0.581 ± 0.100 | 0.598 ± 0.109 | 0.20 | 0.68 | 0.59 | 0.92 | 0.230 ± 0.032 | 0.230 |
| v9 | 0.940 ± 0.045 | 0.823 ± 0.051 | 0.37 | 0.92 | 1.00 | 1.00 | 0.922 ± 0.027 | 0.461 |
| **v9b** | **0.985 ± 0.014** | **0.907 ± 0.027** | 0.74 | 0.92 | 0.97 | 1.00 | **0.969 ± 0.028** | 0.727 |

How these compare with earlier results:
* Same metric as the historical "operational attack macro F1" (fixed 4 classes,
  benign rows included, original labels): recalibrated v5 **0.235**, this BiLSTM
  **0.230**. On the original labels the stage task stays capped by the
  portal-only IC/LM windows and the S4 gate.
* With v9b labels, 161 of 165 attack windows (5 seeds × 33) get the right last
  stage. The other 4 are ED windows the binary head missed, which therefore count
  as benign. No detected attack window gets a wrong stage. One seed raises one
  benign window as ED. The fixed-4
  macro (0.727) is lower only because LM has zero last-stage support, so its
  F1 is 0 by convention.
* The weakest stage is **Initial Compromise presence** (0.74). Each seed has 6–8
  windows where IC is predicted but not labeled. These windows have not been traced individually. A likely cause, not yet verified, is
  that REAPr gives each process one stage even though Word/Firefox act in several.
* Adding the stage loss also **raised binary F1** on v9b (0.952 / 0.971 in the two runs without it → 0.985) and lowered
  its variance. It acts as an extra supervision signal for the shared encoder.
  The validation-selected stage model (seed 42) is in `final_model_stage/`.

### B. LightGBM (Host ML continual boosting) rerun with the new labels

* `code/ML/preprocess/build_host_shards_v9.py` wraps the original builder, changing only
  the `LabelRefiner`: benign-seen seed endpoints are dropped, and each scenario's
  gate = min(configured, first attacker-host connection). Tokens, OpTC frozen vocab,
  benign 1/10 stride, 30:1 train undersampling (seed 42) and split are unchanged.
  The ML rows exclude `FLOW_START`, so the seed rule has almost no effect; the
  gate fix (S3, S4, M5, S1) drives every change.
* Verified: val/test matrices are **bit-identical** to the published legacy build
  (vocab 12,365). Labels only gain positives: test 740 → 802 (+62), val 960 → 1,026,
  train 1,880 → 2,244 (S3 now contributes). None are lost.

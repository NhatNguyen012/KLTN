## 2. Kiểm tra chi tiết cho Mô hình Host ML (LightGBM)

### 2.1. Yêu cầu của LightGBM

LightGBM nhận đầu vào là ma trận thưa nhị phân biểu diễn sự xuất hiện của các **structure-aware semantic tokens** (từ vựng gốc OpTC 10,317 features) qua 7 chiều thông tin.

## 3. Kiểm tra chi tiết cho Mô hình Network DL (BiLSTM)

### 3.1. Yêu cầu của BiLSTM

Theo chuẩn cross-dataset đã phê duyệt, BiLSTM hoạt động trên **cửa sổ trượt 15 phút (900 giây)** theo từng host, sử dụng đúng **5 đặc trưng per-flow**:

1. `app_family` (Categorical $\rightarrow$ Embedding)
2. `image_dir_class` (Categorical $\rightarrow$ Embedding)
3. `proto` (Categorical $\rightarrow$ Embedding)
4. `resp_port_class` (Categorical $\rightarrow$ Embedding)
5. `delta_t_log1p` (Continuous float: $\ln(1 + \max(0, \Delta t))$)

## 4. Đánh giá và Khuyến nghị Lựa chọn Nguồn Dữ liệu

Trong `DATASET/DARPA-TC-E3-THEIA/`, chúng ta có 2 nguồn dữ liệu có thể dùng làm đầu vào cho pipeline:

### So sánh Nguồn Dữ liệu

| Tiêu chí                                            | Nguồn A: Parquet Files (`Parquet/*.parquet`)                                                                                                                                                                          | Nguồn B: Raw JSON Archives (`RAW/*.json.tar.gz`)                                                                                                                 |
| :---------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Dung lượng & Tốc độ nạp**               | **Vượt trội:** `event_table.parquet` chỉ **512 MB**, `process_node_table.parquet` chỉ **11 MB**. Tốc độ nạp vào bộ nhớ chỉ mất vài giây.                                           | **Chậm hơn:** 4 file `.tar.gz` nén tổng cộng gần **3 GB** (khi bung ra hơn 40 GB JSON). Phải streaming qua `tarfile` và parse JSON string. |
| **Mức độ hoàn thiện liên kết đồ thị** | **Đã liên kết hoàn chỉnh:** Đã có sẵn các chỉ mục `index_id` nối trực tiếp giữa Event $\leftrightarrow$ Process $\leftrightarrow$ File $\leftrightarrow$ Netflow.                         | Cần phải tự duy trì từ điển UUID $\rightarrow$ Entity trong RAM khi streaming.                                                                             |
| **Độ phủ nhãn Ground-Truth**                | **100% (126/126 attack processes)** khớp chính xác giữa `theia_labels.csv` và `process_node_table.parquet`.                                                                                               | 100% khớp với `Subject.uuid`.                                                                                                                                   |
| **Các trường thông tin chi tiết**          | Đầy đủ `path`, `cmd`, `src_addr`, `src_port`, `dst_addr`, `dst_port`, `operation`, `timestamp`. ### Khuyến nghị Kiến trúc

1. **Sử dụng `Parquet/*.parquet` làm nguồn dữ liệu chính** cho pipeline tiền xử lý `IL/dataset_2-THEIA/code/preprocess/` để xây dựng shards cho cả LightGBM và BiLSTM. Điều này sẽ giúp pipeline chạy nhanh hơn gấp 15–20 lần so với việc parse lại toàn bộ raw JSON mà vẫn bảo đảm 100% thông tin cần thiết.
2. **Khớp nhãn Ground-Truth 2 tầng:** Kết hợp `theia_labels.csv` (126 node tiến trình độc hại) và `theia_edge_labels.tar.gz` (`edge_labels.csv` chứa ID sự kiện độc hại) để gán nhãn cho cả cấp độ Event (cho LightGBM) và cấp độ Cửa sổ 15 phút (cho BiLSTM).
3. **Thích ứng Domain Shift (Linux vs Windows):** Trong adapter của THEIA, chỉ cần chuyển đổi các nhóm thư mục chuẩn Linux (`/bin`, `/usr/bin`, `/home/`, `/tmp/`) và nhóm file cấu hình `/etc/` vào hệ token cấu trúc tương thích với LightGBM và BiLSTM của OpTC.
